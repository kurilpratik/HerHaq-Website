## HIGH

### 1. Muted text fails WCAG AA (R-25) -- FIXED

Fixed 28 November 2026. `--ink-faint` is now `#746b68`, measured at 4.87:1
on `--paper` and 5.19:1 on white. All fifteen measured pairs pass.

`--ink-faint: #8a807d` measures **3.60:1** on `--paper` and **3.84:1** on white
rows. AA needs 4.5:1 for normal text. It is not decorative: it carries the
masked PAN, the "not given" cells, and the footer line that tells people their
views are logged.

Fix: `#746b68`, which measures 4.87:1 on paper and 5.19:1 on white and keeps
the same warm hue. One variable in `src/styles/admin.css`.

### 2. Tap targets under 44px on a phone (R-03) -- FIXED

Fixed 28 November 2026. Re-measured at 375px: sort links 46x44, reveal link
106x44, sign out 78x44. The rule is scoped to `(max-width: 700px),
(pointer: coarse)`, so a touch laptop gets the larger targets too.

Measured at 375px wide:

| Control | Size | Needs |
| --- | --- | --- |
| Column sort links in `thead` | 46 x 17 | 44 high |
| "Show PANs in full" | 106 x 19 | 44 high |
| "Sign out" | 78 x 34 | 44 high |

The filter button, the tab links and the download buttons already pass. Fix is
padding on those three, which costs a little vertical space in the table head.

### 3. No loading state (R-27) -- ACCEPTED

Accepted 28 November 2026, your call, and written up under **How it works**
in `docs/ADMIN.md`: why there is no spinner, what it costs on a cold Neon
compute, and where to look first if the wait becomes a complaint.

Empty and error states exist and were exercised. Loading does not, because the
pages are server-rendered with no client JavaScript, so the only progress
indicator is the browser's own.

This is worth a decision rather than a reflex. Neon scales the compute to zero
after five minutes idle, so the first admin page load after a quiet spell
genuinely waits, with nothing on the page to say so. The honest options are to
accept it and say so in the audit, or to add a small inline script that marks
the submit button busy on navigation, which would be the first client-side
JavaScript on these pages and slightly weakens "donor data never reaches a
client bundle".

My suggestion: accept it, with a line in `docs/ARCHITECTURE.md`.

### 4. Google Fonts is a third-party request on every admin page (R-40) -- FIXED

Fixed 28 November 2026. Poppins is self-hosted from `/fonts`, nine woff2
files across three weights and three subsets, with the OFL licence beside
them. Verified: an admin page load now makes zero requests to any Google
host, and fetches five font files from this origin.

`AdminLayout.astro` and `login.astro` both pull Poppins from
`fonts.googleapis.com` in `<head>`, which blocks the first render and tells
Google each time somebody opens donor records.

R-40's letter covers render-blocking third-party *scripts*, so this is not a
strict violation, but it is the same problem on a page of personal data. Fix is
to self-host the three Poppins weights used here, or to fall back to the system
stack and drop the request entirely.

## LOW

### 6. No dark mode, and no toggle (R-21, R-34)

The admin ships a single light theme. The rule asks for a working light and
dark toggle unless the product has a specific reason for a fixed theme. The
reason here is that it matches the public site, which is light only, and the
dial is ENERGY 1. Worth confirming you agree rather than letting it pass
silently, since this is a tool staff may use at night.

### 7. Palette runs to four hues, not three plus an accent (R-29)

Core maroon and warm neutrals, amber as the single accent, and then green
(`--success-ink`) and slate (`--slate-ink`) for status tints. The purpose is
real: four lifecycle states have to be distinguishable at a glance in a long
table, and every tint is paired with a word so colour never carries the meaning
alone. Still a deviation from the two to three plus one rule, and worth naming.

### 8. The sticky table header does not stick (C-1)

`thead th` is `position: sticky; top: 0`, but `.table-wrap` has `overflow-x:
auto` and never scrolls vertically, so the header sticks to a scrollport that
does not move. Measured: `scrollsVertically: false`. The CSS does nothing.

Either give the wrapper a `max-height` so it scrolls and the header earns its
keep, or delete the three lines.

### 9. The login logo is announced twice (R-39) -- FIXED

Fixed 28 November 2026. `alt=""`, with a comment saying why.

`login.astro` has `<img alt="Her Haq">` directly above `<h1>Her Haq donations
admin</h1>`. A screen reader reads the name, then reads it again. The image is
decorative in that context, so `alt=""` is correct. The header logo in
`AdminLayout.astro` already does this properly.

### 10. The 10BD download quietly overrides the status filter (C-2) -- RESOLVED

Closed on 28 November 2026 by removing the Form 10BD export altogether, at
your request. There is now one download, it honours the filter bar, and
nothing overrides anything.
